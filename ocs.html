OCS Inventory

OCS Inventory a été installé sur un serveur Linux pour recenser automatiquement les ordinateurs et appareils du parc (Linux, Windows, Android) dans une interface web.

Objectif

Un parc informatique mélange des matériels, des systèmes (Linux, Windows, macOS) et des logiciels en versions différentes. OCS Inventory remonte automatiquement ces informations vers un point central. L'administrateur peut ainsi répondre aux questions du quotidien : quelles versions de Windows sont installées, quels postes ont un disque presque plein, où se trouve tel matériel.

OCS fonctionne en mode client/serveur, avec quatre éléments :

  • Les agents sont installés sur chaque machine (Windows, Linux, macOS, Android) et envoient ses informations au serveur.
  • Le serveur de communication reçoit, classe et archive ces informations.
  • Le serveur d'administration est l'interface web qui permet de consulter les inventaires et de gérer les droits des utilisateurs.
  • Le serveur de déploiement permet de diffuser logiciels et mises à jour depuis un point central.

Ce type d'outil s'inscrit dans les bonnes pratiques ITIL, le référentiel utilisé par les directions des systèmes d'information.

Environnement

ÉlémentChoix retenu
ServeurMachine Linux nommée « ocs »
Pile webLAMP : Linux, Apache (serveur web), MariaDB (base de données), PHP
Version d'OCSServeur pour Linux 2.11.1
Base de donnéesBase « dbocs » avec un utilisateur dédié
AccèsPar l'adresse IP, puis par le nom ocs.sitka.local
Agents testésLinux, Windows (agent 2.9.0.0) et Android

Étapes de mise en place

  1. Préparer la machine : mise à jour du système et renommage en « ocs ».
  2. Installer le serveur LAMP : Apache, MariaDB et PHP. Un test depuis un navigateur confirme que le serveur web répond. Un avertissement sur le nom de domaine est corrigé avec un petit fichier de configuration.
  3. Sécuriser la base de données : l'assistant de sécurité de MariaDB définit le mot de passe administrateur, supprime les utilisateurs anonymes, interdit la connexion distante du compte root et supprime la base de test.
  4. Créer la base d'OCS : une base dédiée et un utilisateur qui n'a de droits que sur elle. Des requêtes de vérification confirment que tout est bien créé.
  5. Installer les dépendances : les modules Perl et PHP dont OCS a besoin pour fonctionner.
  6. Installer OCS : téléchargement de l'archive du serveur, puis lancement du script d'installation en gardant les valeurs proposées par défaut.
  7. Relier OCS à la base : le nom de la base et celui de l'utilisateur sont renseignés dans les fichiers de configuration d'OCS.
  8. Activer la configuration Apache : les trois fichiers d'OCS (serveur, API REST, interface de rapports) sont activés, puis Apache est redémarré.
  9. Terminer l'installation par l'interface web : saisie des informations de la base, mise à jour proposée par OCS, puis connexion avec le compte par défaut. Une alerte de sécurité demande de renommer le fichier d'installation. Une fois fait, l'alerte disparaît.
  10. Accéder par un nom de domaine : un enregistrement « ocs » est créé sur le serveur DNS et un hôte virtuel est ajouté dans Apache, pour joindre le serveur avec ocs.sitka.local.
  11. Déployer les agents : sous Linux, installation de l'agent en choisissant la méthode http et l'adresse du serveur OCS. Sous Windows, téléchargement de l'agent puis saisie de l'adresse du serveur (pas de proxy), et l'inventaire est lancé depuis l'icône OCS. Sous Android, installation de l'agent mobile et envoi de l'inventaire : le serveur reçoit pour cela une deuxième carte réseau en mode bridge, afin que le smartphone puisse l'atteindre.

Résultat et vérification

Après l'envoi de leur inventaire, les machines Linux, Windows et Android apparaissent dans la liste de l'interface web d'OCS. La vérification se fait en consultant cette liste des machines remontées.
